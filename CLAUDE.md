# Фид КП «Счастье» — инструкция для Claude

XML-фид (формат Циан 2.0) коттеджного посёлка «Счастье» для **Домклика и ЦИАН**.
Публикуется GitHub Pages из папки `docs/` ветки `main` (репозиторий публичный):

- фид: https://dpoleschukbm-creator.github.io/kp-schastye-feed/feed.xml
- фото с номерами: https://dpoleschukbm-creator.github.io/kp-schastye-feed/photos.html

Правки приходят словами («дом 100 м², фото 7 заменить на файл из загрузок, цена 8,5 млн»).
Делай всё сам: обновить репо → правка → сборка → проверка → коммит → пуш → проверка живого фида.
Отчитывайся коротко, по-русски, без кода.

**Спорное — спрашивай.** Если параметр противоречит описанию или фото (ремонт, терраса, сотки…),
задай вопрос. Бесспорные правки из той же просьбы публикуй сразу, спорную — отдельным
коммитом после ответа.

## 0. Начало работы

```
git pull --ff-only
git status
```

Если `pull` не проходит или есть чужие незакоммиченные изменения — остановись и спроси.
При конфликте в `docs/*` (они генерируются) бери `data/` и `build.py` из `main` и пересобирай.

## Где что править

| Что | Где |
|---|---|
| Цена, площадь дома, сотки, этажность, год, стены, вода, терраса, баня | `data/objects.json` |
| Ремонт и состояние отдельного дома | `"repair"`, `"condition"` в `data/objects.json` |
| Точечная правка текста описания | `"descReplace": [["было", "стало"], ...]` в `data/objects.json` |
| Описание целиком | поле `desc` объекта в `data/avito_media.json` |
| Фото | `docs/photos/<avitoId>/*.jpg` |
| Сборка | `build.py` → `docs/feed.xml` и `docs/photos.html` |

`docs/feed.xml` и `docs/photos.html` **генерируются — руками не править.**

Поля `objects.json`:
- `avitoId` — ключ объекта (ExternalId в фиде = `kps-<avitoId>`). Объект в разговоре называют
  по `photos.html`: «Дом 100 м²», «Участок 6 сот.».
- `category` — **обязательное**: `house` (дом) | `land` (участок).
- `title` и `rooms` — служебные, **в фид не попадают**. Заголовок объявления Домклик и ЦИАН
  строят сами из параметров (площадь, сотки). Тег `Title` у ЦИАН работает только с платным
  продвижением «Топ»/«Премиум», поэтому мы его не используем.
- `price` (₽), `houseArea` (м²), `landSotka` (сотки), `floors`, `buildYear`.
- `walls`: `brick`, `solidWood`, `gluedLaminatedTimber` и др. (MaterialType ЦИАН).
- `water`: `well` (колодец), `borehole` (скважина).
- `terrace`, `bathhouse`: true/false.
- `repair`: `cosmetic` | `euro` | `design` | `no` (по умолчанию `no`).
- `condition`: `ready` (готов к проживанию) | `interiorDecorationRequired` (без внутренней
  отделки, по умолчанию) | `majorRepairsRequired` | `unfinished`.
- `removedPhotos`: имена файлов, заменённых своими фото (их не докачивать и не публиковать).

**Ремонт — всегда тройкой.** ЦИАН требует, чтобы тип ремонта соответствовал фото.
Ставя `repair` ≠ `no`: посмотри фото дома (`photos.html`), поставь `condition: "ready"`
и через `descReplace` убери/перепиши фразы «white box», «ремонт можно заказать» и т. п.
Снимая ремонт — наоборот.

## Описания

- В `avito_media.json` тексты с Авито, где часть букв — латинские двойники. `clean_description()`
  чинит их сам; новый текст пиши обычной кириллицей.
- Скрипт заменяет `&` → «и», `/` и `\` → «, », удаляет `№`, эмодзи (ЦИАН их запрещает или
  вырезает). Это применяется и к «стало» из `descReplace`.
- В `descReplace` фрагмент **«было» копируй из `docs/feed.xml`** (уже очищенный текст), а не из
  `avito_media.json` — иначе сборка упадёт «в описании нет фрагмента».
- Длина 15–7000 символов (скрипт проверяет).
- **Не писать «от N соток»** про один объект: ЦИАН отклонял такое объявление как «несколько
  объектов». Писать «участок 13 соток».
- Попутно исправляй явные опечатки и говори, что исправлено.

## Замена фото

1. Номер → файл: открой `docs/photos.html`, найди у объекта плитку с нужным номером
   (`aria-label="…, фото N"`), её `href` — это файл. Номер ≠ имя файла: дубли (одинаковый md5)
   в фид не попадают, и нумерация сдвигается.
2. ЦИАН не перекачивает картинку по старой ссылке → новое фото кладём **под новым именем**:
   имя заменяемого файла + суффикс через дефис, `13.jpg` → `13-new.jpg` (дефис сортируется раньше
   точки, фото встанет ровно на место старого). Порядок фото = сортировка имён, первое — главное.
3. Проверь дубли заменяемого файла:
   `Get-FileHash -Algorithm MD5 docs\photos\<id>\*.jpg | Group-Object Hash | ? Count -gt 1`.
   Если у него есть копия — её тоже впиши в `removedPhotos`, иначе старое фото вернётся в объявление.
4. Старый файл удали (`git rm`) и впиши его имя в `removedPhotos` объекта.
5. Исходник ищи в «Загрузках» (папка может быть перенесена в OneDrive):
   `(New-Object -ComObject Shell.Application).NameSpace('shell:Downloads').Self.Path`.
   Исходник в репозиторий не клади — в `docs/photos/` только готовый `.jpg`.
6. Скрипт берёт только `*.jpg`. PNG и т. п. конвертируй (прозрачность → белый фон):

```powershell
Add-Type -AssemblyName System.Drawing
$src = "<полный путь к исходнику>"
$dst = "<полный путь>\docs\photos\<avitoId>\<имя>-new.jpg"   # только полные пути
$img = [System.Drawing.Image]::FromFile($src)
$bmp = New-Object System.Drawing.Bitmap $img.Width, $img.Height, ([System.Drawing.Imaging.PixelFormat]::Format24bppRgb)
$g = [System.Drawing.Graphics]::FromImage($bmp); $g.Clear([System.Drawing.Color]::White)
$g.DrawImage($img, 0, 0, $img.Width, $img.Height)
$enc = [System.Drawing.Imaging.ImageCodecInfo]::GetImageEncoders() | Where-Object MimeType -eq 'image/jpeg'
$ep = New-Object System.Drawing.Imaging.EncoderParameters 1
$ep.Param[0] = New-Object System.Drawing.Imaging.EncoderParameter([System.Drawing.Imaging.Encoder]::Quality, [long]92)
$bmp.Save($dst, $enc, $ep); $g.Dispose(); $bmp.Dispose(); $img.Dispose()
```

   WebP/HEIC `System.Drawing` не читает — попроси прислать JPG или PNG.
7. После сборки число фото у объекта не должно измениться (если это замена, а не добавление).

## Новый объект

Запись в `objects.json` (с `category`), запись в `avito_media.json` с ключами `desc` и `imgs`
(ссылки на фото), затем `python build.py --photos`.

## Сборка

```
python build.py              # feed.xml + photos.html
python build.py --photos     # + докачать недостающие фото с Авито
```

Python нужен только стандартный (3.9+). Если на ПК его нет (на Windows `python` может быть
заглушкой Microsoft Store), скачай портативный `python-3.12.10-embed-amd64.zip` с python.org,
распакуй во временную папку и запускай `python.exe -I -X utf8 build.py` из корня репозитория.

Перед правками прогони сборку на чистом репо: `git diff` должен быть пустым — значит, сборка
на этом ПК даёт то же, что опубликовано. Файлы пишутся с LF, `.gitattributes` держит LF в git.

## Проверка перед пушем

- `git diff docs/feed.xml` — меняется только то, что просили (и фото — ровно на нужной позиции).
- XML парсится, объектов столько же, у каждого ровно одно `IsDefault=true` фото.
- Пара `RepairType` / `Condition` и описание не противоречат друг другу и фото.
- Если правка меняет факты из раздела «Текущее состояние» ниже — обнови его в том же коммите.

## Публикация

- Коммит прямо в `main` (Pages публикует из `main/docs`), сообщение по-русски в стиле
  `git log` (`feat: …` / `fix: …`). В коммит — только `data/`, `docs/`, `build.py`, документация.
- **Автор — всегда владелец репозитория**, даже если на ПК настроен другой (рабочий) git-аккаунт:
  `git -c user.name="<%an из git log -1>" -c user.email="<%ae из git log -1>" commit …`.
  Глобальный конфиг не трогай.
- Если `git push` просит вход — откроется окно Git Credential Manager; попроси владельца войти в
  GitHub там. Токены и пароли в чат не запрашивай.
- После пуша опрашивай `feed.xml?t=<случайное>` раз в 30 с, до 5 минут, пока не увидишь новые
  значения. Новые фото проверь по прямому URL (HTTP 200) и что `photos.html` обновился.
  Домклик подтягивает изменения в течение ~2 часов, ЦИАН — при очередном обходе.

## Справка

- Требования ЦИАН к фиду: https://www.cian.ru/xml_import/doc/ — WebFetch упирается в капчу,
  страница открывается в настоящем браузере. Ищи по имени тега (`RepairType`, `Condition`).
- Домклик принимает фиды в формате ЦИАН с теми же требованиями.
